Lesson 3.2 — Naming, Versions and Evidence

Practice file: Wattlebird Sandbox Pack v2.3.4 — fictional training data. Work from a copy.Open the Wattlebird practice file

1. Progress Reminder

You now have a place for your work.

Next, make each file identifiable.

A useful filename should answer:

What is it? Which module or task? Which version? When relevant, what date applies?

← Module 3 overview

2. Why This Matters

Consider these filenames:

  • final-final roster.xlsx
  • Invoice new 2.xlsx
  • Grace agreement latest.docx
  • handover.docx

You may understand them today.

Another person opening the folder later may not.

Clear naming reduces uncertainty and makes handover easier.

3. Learn

A predictable pattern can look like:

Module → Artifact → Version → Date when useful

For example:

M09_RosterCheck_v1_2026-11-04

The course's M16_Portfolio examples also show naming patterns such as:

01_M1_Profile_v1

The exact pattern can vary by provider.

The important habits are:

  • use meaningful words;
  • use a consistent order;
  • identify versions clearly;
  • avoid vague words such as new, latest, or final-final;
  • preserve earlier versions when the workflow requires evidence of change.

8. Work Boundary

A filename should describe what the file actually is.

Do not label a document:

  • FINAL when approval is still pending;
  • APPROVED when nobody authorized it;
  • SIGNED when it has not been signed;
  • COMPLETE when required work remains.

Naming is documentation.

Documentation must remain truthful.
